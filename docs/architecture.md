# Architecture

The static frontend runs on GitHub Pages at `/reading-queue/`. Hash routes support refreshes and direct item links without a server rewrite. Vite includes the base path in assets. Supabase JavaScript owns persistent sessions, refresh tokens, email/password flows, confirmation callbacks, and recovery callbacks. Auth callbacks point to the base URL without a hash, allowing the SDK to consume its token fragment before hash routing starts. Recovery events show a dedicated password form.

Only the public URL and publishable/anon key enter the bundle. PostgreSQL is the source of truth. Query keys and caches are cleared on account changes and logout. Requests use an AbortSignal and debounced search. List queries retrieve 24 items with deterministic ordering. Note saving is debounced by one second and uses explicit version comparisons; failures preserve the text and require retry. Version conflicts display the latest remote text for deliberate merge. Tab-local sessionStorage drafts preserve text and its base version across refresh and expired sessions, scoped by user and item. Recovering an old draft against a newer cloud version requires an explicit merge. These drafts contain private text: clear site data after using a shared device. They are a recovery aid, not offline sync. Closing the tab removes its recovery storage; heed the unload warning until saved.

Database RPCs use SECURITY INVOKER, fixed search paths, RLS, ownership defaults and composite foreign keys. A caller cannot attach another user's tag or note to an item. Save-item and import operations are database transactions. Item edits compare their loaded version; note updates compare their own version and lock the parent first. Direct note updates must advance the version by one; stale explicit versions fail. An item version also changes when its note changes, so concurrent metadata edits may require a reload.

Markdown renders through react-markdown with raw HTML disabled, safe URL transformations, safe external links and no embedded images. Manually entered cover URLs accept only HTTP(S), reject credentials, and use `no-referrer` with a broken-image fallback. They still contact the external image host; there is no image proxy. Browser extensions and remote sites are outside this application's trust boundary.

## Metadata decision

No outbound metadata HTTP request is enabled. Validating DNS and then calling hostname-based fetch does not prevent DNS rebinding. This repository does not establish that Supabase's hosted Edge runtime can connect to only a pinned validated address while preserving TLS/Host. Consequently the Edge Function requires a valid Supabase user and an allowlisted Origin, but returns `available:false`. The UI states the same limitation and never presents fixtures as extracted metadata. The UI avoids calling the disabled endpoint. There is no provider quota, scraping, parsing, image proxy, or outbound-fetch SSRF surface. Before adding an extractor, implement bounded DNS-pinned connections, redirects, timeout, HTML-only response size limits, IP classification including IPv6/mapped IPv4, per-user persistent rate limiting, deterministic parser fixtures and adversarial network tests. This disabled endpoint has no costly fetch operation; it does not claim a per-user rate limiter.

## Scope

Explicit statuses are the only progress measure. No external scrolling measurement, offline synchronization, reader mode, social sharing, analytics, or AI summaries are included. Session refresh failure prevents cloud writes; retain the tab draft, sign in again, then resolve versions. Database and provider errors are converted to actionable UI errors rather than exposing SQL details.
